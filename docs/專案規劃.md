# 個人翻譯網站 — 專案討論摘要

## 專案概念

小圈子青空文庫/古騰堡計畫翻譯協作站,以 GitHub 為核心基礎設施,零維運成本、盡可能開放授權,重視內容的長期保存價值。

- **核心原則**:不自建後端、不自建資料庫、不自建使用者系統,全部借用 GitHub 既有機制
- **協作模式**:譯者開 PR 提交,審核後 merge
- **翻譯者誘因**:無金錢報酬,靠瀏覽次數/喜歡數紀錄、個人 profile 頁面

## 技術組合

| 項目 | 方案 |
|---|---|
| 內容儲存/協作 | GitHub repo(PR 提交 → review → merge) |
| 版本控制 | Git history(天生留存修訂紀錄) |
| 網站託管 | GitHub Pages **與** Cloudflare Pages 同時部署(互為備份,避免鎖定單一平台) |
| 建置流程 | 純 Node.js build script,輸出純靜態檔案(避免用到 Cloudflare Workers/KV 或 Jekyll 專屬語法,保持可攜性) |
| 互動效果 | 純 JS/CSS |
| 站內搜尋/標籤過濾 | 前端 fetch `articles.json`,JS 在記憶體中 filter;量大再上 Pagefind |
| EPUB 匯出 | 瀏覽器端 JSZip,純 client-side(細節未討論) |
| 授權 | CC BY-SA / CC BY-NC-SA(repo LICENSE 聲明,細節未定) |
| 使用者系統 | 借用 GitHub 帳號 |
| SEO | sitemap.xml + meta 標籤 + Google Search Console(細節未討論) |

## 已定案的架構決策

### 資料結構

```
/translations/譯者/作品ID.md   ← 原始內容,frontmatter + 正文
/CONTRIBUTING.md
/LICENSE
```

### Build 輸出結構

```
/articles/{uuid}/index.html    ← 單篇文章,build 時全文直接灌入,純靜態,不依賴 JS 才能顯示內容
/articles.json                  ← 全站文章 metadata(不含全文),給前端搜尋/篩選用
/tags/{tag}/index.html          ← 標籤索引頁,列出摘要+連結,不重複存全文
/translators/{name}/index.html  ← 譯者索引頁,同上邏輯
```

**關鍵原則**:每篇文章只有一份實體內容(`/articles/{uuid}/`),標籤頁、作者頁只是 build script 另外彙整出的「摘要+連結列表」,不是內容的複製品。

### 文章 ID

- **採用 UUID**,不用流水號
- 原因:多人分散式 PR 提交,流水號需要中心化協調(撞號風險、需要 merge 時重新計算),UUID 完全繞開這個問題,天生適合無中心化協作
- Slug(好記網址)**暫緩不處理**,先用 UUID 當檔名/路徑

### Canonical URL(SEO)

- 每篇文章 html 應包含 `<link rel="canonical" href=".../articles/{uuid}/">`,明確標示內容的唯一權威來源

### Hosting / CI/CD

- **Cloudflare Pages 內建 git 整合**:接上 repo、填 build command,push 即自動觸發 build + 部署,**不需要另外寫 GitHub Actions workflow 來觸發**
- GitHub Actions 屬於可選項,若要做 PR 階段檢查(如驗證 frontmatter 格式)可以另外加,跟部署觸發是兩件不衝突的事
- 同時部署到 GitHub Pages + Cloudflare Pages,降低平台鎖定風險

### 開發/測試順序

1. **本機資料夾測試 build script**(不接 repo,不接 hosting),確認 md → html/json 轉換邏輯正確
2. push 測試檔案 + script 到 GitHub repo(仍不接 hosting),確認 git 這層沒問題
3. 最後才接 Cloudflare Pages,驗證自動部署

### URL 設計 / REST 風格的可行範圍

- **可行**:單一資源導向的 URL(`/articles/{uuid}/`、`/tags/{tag}/`、`/translators/{name}/`),但必須是 build 時就窮舉產生的靜態頁面,不能接受任意路徑
- **不可行**:動態多條件查詢組合(如 `?tag=X&translator=Y&sort=Z`)→ 改用前端 JS 記憶體 filter 處理,不對應獨立可分享 URL
- **不可行**:HTTP 寫入動詞(POST/PUT/DELETE)→ 寫入操作走 GitHub PR 流程,不走 HTTP 層
