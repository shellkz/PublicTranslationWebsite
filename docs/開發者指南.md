# 開發者指南

這份指南寫給想改進站台程式碼(build script、頁面渲染、樣式、前端互動)的人。內容資料結構見 [架構規格.md](./架構規格.md);專案整體理念見 [專案規劃.md](./專案規劃.md)。

## 這是什麼樣的專案

- 零後端、零資料庫的純靜態站——`scripts/build.js` 讀 `content/` 底下的 Markdown + frontmatter,產生純 HTML/CSS/JS 到 `dist/`,部署到 Cloudflare(細節見架構規格.md 第 8 節)
- 沒有前端框架、沒有 bundler——頁面渲染是純字串樣板(`scripts/app/*.js` 各自對應一種頁面類型),前端互動是原生 JS(`assets/js/`),刻意保持這樣簡單,新人不需要額外裝環境就能看懂
- 「沒有 JS 也要能用」是硬性限制——任何新加的前端互動,都要先確定資料本身已經完整渲染進 HTML(如 `data-*` 屬性),JS 只負責顯示/隱藏,不負責產生內容

## 本機開發

```
cd scripts
npm install
node build.js
```

輸出在 repo 根目錄的 `dist/`,可以直接用任何靜態伺服器(如 `npx serve dist`)在本機瀏覽。改完 `content/`、`scripts/`、`assets/` 底下的東西後重跑 `node build.js` 就會反映改動,不需要額外的 watch/dev server 設定。

## 你可以做的事

- 修 bug、加頁面功能、調整樣式、補測試用的 fixture 內容
- 調整 `docs/架構規格.md` 描述的資料結構——但這屬於會影響所有既有內容/貢獻者的變動,建議先開 issue 討論再動手
- 新增站台功能(如 EPUB 匯出、SEO meta)——`docs/專案規劃.md`、`docs/架構規格.md` 第 7 節列了目前已知但尚未做的項目,可以挑一項認領

## 你的義務與權利

- `scripts/`、`assets/` 底下的程式碼採 [MIT License](../scripts/LICENSE),提交 PR 即代表同意以此授權釋出你的貢獻——你仍保有貢獻內容的著作權,只是同意讓任何人依 MIT 條款使用
- 改動涉及 `content/` 資料結構(frontmatter 欄位、資料夾規則)時,請同步更新 `docs/架構規格.md`——這份文件是唯一的權威規格,程式碼與文件不一致時,兩邊都要當成 bug 處理

## 提交流程

跟譯者一樣走 GitHub PR,見 [CONTRIBUTING.md](../CONTRIBUTING.md)。PR 通過自動檢查(目前僅在 merge 後的 Cloudflare 部署時執行,見架構規格.md 第 6 節)後即可合併,程式碼改動同樣沒有額外的人工審核關卡——影響範圍較大的改動(如資料結構變更)建議自己先在本機跑過 build 確認沒有破壞既有頁面。
